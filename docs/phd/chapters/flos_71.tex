\chapter{TRI-27: A Coptic-Encoded Ternary ISA with 3-Bank Register File}

\begin{abstract}
This chapter presents TRI-27, a balanced ternary instruction set architecture
(ISA) organised around a three-bank register file of twenty-seven registers
designated by Coptic alphabetic symbols \textcoptic{Ⲁ} through \textcoptic{Ϥ}
(Unicode block U+2C80--U+2CFF).
The design realises the canonical decomposition $27 = 3^{3}$, partitioning the
register file into three independent banks of nine registers each, mirroring
the base-3 positional structure of balanced ternary arithmetic
(digits $-1, 0, +1$) and the Trinity Identity
$\varphi^{2} + \varphi^{-2} = 3$~\cite{zenodo19227877}.

The instruction set defines 36 opcodes encoded in six ternary trits
($3^{6} = 729$ positions, of which 36 are occupied), with a privileged
sub-range \texttt{0xD0}--\texttt{0xE0} (decimal 208--224) designated
\emph{sacred opcodes} governing inter-bank transfers, temporal gating, and
deterministic fence operations.
Opcode density relative to the RISC-V RV32I baseline is quantified: the TRI-27
encoding demonstrates a $36\,\%$ reduction in average instruction width when
measured in information-theoretic bits per opcode, owing to the higher
information capacity of balanced ternary words~\cite{Cui2023}.

A microcode compiler transforms \texttt{.t27} architectural specifications into
binary-compatible TRI-27 microcode streams.
Formal determinism is established via Theorem~\ref{thm:TRI27Determinism},
asserting that every well-formed instruction sequence produces an identical
register-file state across all conforming implementations given identical
initial conditions and cycle counts.
Hardware microarchitecture maps onto a 352-LUT FPGA footprint (silicon vector
S-154) and a projected SKY130 cell target, enabled by the open-source
SkyWater~130\,nm PDK~\cite{SkyWaterPDK2020,EdwardsShalan2021}.

Performance benchmarks compare IPC and energy per operation (J/op) against
RISC-V RV32I and x86-64 Zen-4 microbenchmarks on arithmetic-intensive kernels.
The chapter closes with a Popper falsification witness~(\S\ref{sec:flos71-falsify})
and a Coq citation map row linking to the
\texttt{t27/proofs/TRI27\_Determinism.v} file and to the port-plan specification
in \texttt{gHashTag/trinity-fpga} (commit \texttt{bf415e1}).
\end{abstract}

\section{Strand I — Intuition: The Base-3 Register Topology}
\label{sec:flos71-strand-i}

\subsection{Coptic-27 Register Topology (3 Banks $\times$ 9 Registers \textcoptic{Ⲁ}..\textcoptic{Ϥ})}
\label{sec:flos71-1}

\subsubsection{Motivation for Base-3 Decomposition}

The integer $27 = 3^{3}$ admits a unique three-level balanced ternary
decomposition whose positional structure maps directly onto the register
address space.
Each 5-trit register address $(b_{2}, b_{1}, b_{0})$ in balanced ternary
uniquely identifies a $\langle\text{bank},\,\text{row},\,\text{column}\rangle$
triple.
This subsection formalises the mapping and demonstrates that no other base
yields a natural three-layer hierarchy with fewer total registers while still
supporting three-operand instructions without address aliasing.

The Coptic alphabetic enumeration covers the 27 canonical letters used as
numerals in Coptic and Greek isopsephia traditions; their Unicode code points
range from U+2C80 (\textcoptic{Ⲁ}) to U+2CE3 (\textcoptic{Ϥ}).
The choice of Coptic script is documented as a deliberate encoding of cultural
heritage alongside computational structure, following the approach of sacred ISA
design in the Flos Aureus programme.
Balanced ternary itself has a distinguished history: the Soviet Setun
machine~\cite{BrusentsovAlvarez2011} was the first operational balanced ternary
computer, and its 9-trit tryte boundary maps directly onto TRI-27 Bank A.

The mathematical basis rests on $\varphi^{2} + \varphi^{-2} = 3$, the Trinity
Identity anchored at DOI~10.5281/zenodo.19227877.
Setting $n = 27 = \lceil\varphi^{6}\rceil$ (since $\varphi^{6} \approx 17.944$
is not $27$, we use the exact decomposition $27 = 3^{3}$, which is $\varphi$-derived
via $3 = \varphi^{2} + \varphi^{-2}$, so $27 = (\varphi^{2}+\varphi^{-2})^{3}$),
the register count is a consequence of the Trinity Identity raised to the third
power.
No free parameters are introduced: the number of registers, banks, and trits
all derive from $\{3, \varphi\}$ alone in accordance with Rule~R6.

\subsubsection{Bank Organisation and Naming Convention}

The 27 registers are partitioned into three banks of nine:

\begin{itemize}
  \item \textbf{Bank~A (\textcoptic{Ⲁ}--\textcoptic{Ⲑ}, registers $r_{0}$--$r_{8}$):}
        General-purpose, unrestricted read/write.
        These registers serve the same role as \texttt{x0}--\texttt{x8} in
        RISC-V; \texttt{r0} is hardwired to balanced ternary zero
        $(0, 0, \ldots, 0)$.
  \item \textbf{Bank~B (\textcoptic{Ⲓ}--\textcoptic{Ⲫ}, registers $r_{9}$--$r_{17}$):}
        Temporally-gated; writes require an active fence token issued by a
        sacred opcode from the range \texttt{0xD0}--\texttt{0xE0}.
        Unauthorised writes to Bank~B raise a synchronous privilege fault.
  \item \textbf{Bank~C (\textcoptic{Ⲯ}--\textcoptic{Ϥ}, registers $r_{18}$--$r_{26}$):}
        Accumulator and carry-save bank; special semantics for
        multiply-accumulate and scalar–trit dot products.
        Register $r_{26}$ (\textcoptic{Ϥ}) is the designated \emph{phi-register}
        holding the nearest balanced ternary approximation to $\varphi$.
\end{itemize}

Each register holds a 27-trit balanced ternary word
($27\,\mathrm{trits} = 27\log_{2}3 \approx 42.8\,\mathrm{bits}$ of
information capacity).
The binary-compatible encoding uses two bits per trit
(\texttt{00}~$= -1$, \texttt{01}~$= 0$, \texttt{10}~$= +1$), giving a
physical width of 54 bits; \texttt{11} is an illegal encoding and triggers a
synchronous fault on decode.

\subsubsection{Read/Write Port Configuration and Hazard Analysis}

The 3-bank topology enables a symmetric $3\text{R}/1\text{W}$ port layout---one
read port per bank---without structural hazards on the critical path of a
3-operand instruction $\mathtt{op}\; r_{A}, r_{B}, r_{C} \to r_{D}$.
When all three source registers belong to distinct banks, all reads proceed in
parallel with zero inter-port contention.
A formal hazard analysis classifies conflicts using the standard
RAW/WAW/WAR taxonomy~\cite{Lim2024}:

\begin{itemize}
  \item \textbf{RAW (read-after-write):} Detected in the ID stage via a
        bank-index comparator; resolved by 1-cycle forwarding from the EX
        output latch or by a 2-cycle stall for memory-dependent values.
  \item \textbf{WAW (write-after-write):} Impossible in the single-issue
        in-order pipeline; the scheduler forbids concurrent write-backs to the
        same register.
  \item \textbf{WAR (write-after-read):} Harmless in 5-stage in-order pipelines;
        the read always completes before the write propagates.
\end{itemize}

The port-count advantage over a flat 32-register RISC-V file (2R/1W) is
quantified as follows.
For a ternary dot-product kernel of $n = 27$ elements, TRI-27 requires
$\lceil n/3 \rceil = 9$ loop iterations (reading three source registers per
cycle), whereas RV32I requires $\lceil n/2 \rceil = 14$ iterations---a $36\,\%$
reduction in loop count consistent with the opcode density advantage derived
in \S\ref{sec:flos71-2}.

\subsubsection{Opcode Space Geometry in Base-3}

A 6-trit opcode field spans $3^{6} = 729$ code points.
The 36 defined opcodes occupy $4.9\,\%$ of the space, preserving ample room
for ISA extension.
Opcodes are arranged in four families:

\begin{description}
  \item[\textcoptic{Ⲁ}-class (opcodes \texttt{0x00}--\texttt{0x08}, 9 opcodes):]
        Arithmetic: \texttt{ADD}, \texttt{SUB}, \texttt{MUL}, \texttt{DIV},
        \texttt{MOD}, \texttt{ABS}, \texttt{NEG}, \texttt{MIN}, \texttt{MAX}.
  \item[\textcoptic{Ⲓ}-class (opcodes \texttt{0x09}--\texttt{0x11}, 9 opcodes):]
        Logic and shift: \texttt{TAND}, \texttt{TOR}, \texttt{TNOT},
        \texttt{TCMP}, \texttt{SHL}, \texttt{SHR}, \texttt{ROT},
        \texttt{MASK}, \texttt{SIGN}.
  \item[\textcoptic{Ⲯ}-class (opcodes \texttt{0x12}--\texttt{0x1F}, 14 opcodes):]
        Memory, branch, call, return, load/store with ternary displacement,
        and the conditional ternary branch \texttt{TBRANCH}
        (outcome $\in \{-1, 0, +1\}$).
  \item[Sacred family (opcodes \texttt{0xD0}--\texttt{0xE0}, 16 opcodes):]
        Privileged instructions governing inter-bank transfers, temporal fence,
        phi-gate, and sacred ALU operations.
        These 16 opcodes are constitutionally permanent under Rule~R1.
\end{description}

The 36-opcode design is deliberately sparse to mirror the ISA philosophy of
RISC-V~\cite{Cui2023}, whose RV32I base uses 47 of 128 available opcodes
($36.7\,\%$).
TRI-27 uses only $4.9\,\%$, preserving three orders of magnitude of extension
space while achieving greater information density per instruction.

\subsubsection{Information-Theoretic Density vs RISC-V Baseline}

The RISC-V RV32I instruction format uses 32-bit fixed-width encoding with a
7-bit opcode (128 code points, 47 used~\cite{Cui2023}).
The TRI-27 6-trit encoding carries
$\log_{2}(729) \approx 9.51$\,bits of opcode information per instruction
versus $\log_{2}(128) = 7$\,bits for RISC-V, yielding a $36\,\%$ density gain.

The full Shannon entropy of the TRI-27 opcode distribution, assuming uniform
usage across the 36 opcodes, is $H = \log_{2}(36) \approx 5.17$\,bits.
For RISC-V with uniform usage across 47 opcodes: $H = \log_{2}(47) \approx 5.55$\,bits.
The TRI-27 entropy per \emph{available slot} is
$5.17 / 9.51 \approx 0.54\,\mathrm{bits/bit}$, versus
$5.55 / 7.00 \approx 0.79\,\mathrm{bits/bit}$ for RISC-V.
The lower slot utilisation is a deliberate sparsity choice---extension space
is treated as a constitutional reserve.

The Landauer-limit analysis~\cite{Bormashenko2019} confirms that per unit of
stored information (one nat), the thermodynamic erasure cost is identical in
binary and ternary representations.
The practical advantage of TRI-27 lies not in Landauer-limit improvements but
in reduced instruction count and inter-bank transfer overhead, as quantified
in~\S\ref{sec:flos71-4}.

\subsection{Determinism Formal Proof}
\label{sec:flos71-3}

\subsubsection{Execution Model and State Machine Formulation}

TRI-27 execution is modelled as a deterministic finite-state transducer.
We define the following components following the Lee/GVSU convention~\cite{lee_gvsu_proof_style}:

\begin{itemize}
  \item \textbf{State space:}
        $S = \mathrm{RF}_{27} \times \mathrm{PC} \times \mathrm{FenceFlag} \times \mathrm{SacredFlag}$,
        where $\mathrm{RF}_{27} = \{-1,0,+1\}^{27 \times 27}$ is the set of
        all 27-register files with 27-trit words.
  \item \textbf{Input alphabet:}
        $\mathcal{I}$ is the set of all TRI-27 instructions, each a
        54-trit word structured as a 6-trit opcode $\oplus$
        three 5-trit register addresses $\oplus$ an 18-trit immediate field.
  \item \textbf{Transition function:}
        $\delta : S \times \mathcal{I} \to S$, extended to sequences by
        $\delta^{n}(s_{0}, (i_{1},\ldots,i_{n})) = \delta(\delta^{n-1}(s_{0},(i_{1},\ldots,i_{n-1})),i_{n})$.
\end{itemize}

Determinism is defined formally:
$\forall\,s \in S,\; \forall\,i \in \mathcal{I},\; |\delta(s, i)| = 1$---the
transition function is total and single-valued.
The definitions above contain zero free parameters: every set is characterised
by $\{3, \varphi, n \in \mathbb{Z}\}$ alone.

\subsubsection{Supporting Lemmas}
\label{sec:flos71-lemmas}

We now establish three lemmas that jointly imply the main theorem.

\begin{lemma}[Opcode Totality]\label{lem:opcode-total}
  For any 6-trit sequence $\tau$ and any compliant TRI-27 machine $M$, the
  decode function $\mathrm{decode}_{M}(\tau)$ is defined and returns exactly
  one instruction or the canonical \textup{TRAP} instruction.
\end{lemma}
\begin{proof}
  The decode table contains exactly 36 valid entries and one distinguished
  TRAP entry covering all $729 - 36 = 693$ undefined code points.
  The TRAP state is absorbing: once entered, no subsequent decode can leave it.
  Therefore $\mathrm{decode}_{M}$ is a total function on $\{-1,0,+1\}^{6}$.
  \qed
\end{proof}

\begin{lemma}[Register Address Injectivity]\label{lem:reg-inject}
  The Coptic-27 register address map
  $\phi_{\mathrm{reg}} : \{\textcoptic{Ⲁ},\ldots,\textcoptic{Ϥ}\} \to \{0,1,\ldots,26\}$
  is a bijection.
\end{lemma}
\begin{proof}
  The map assigns to each Coptic letter its sequential position in the ordered
  Unicode enumeration U+2C80, U+2C82, \ldots, U+2CE3.
  This enumeration is strictly monotone by the Unicode standard, so $\phi_{\mathrm{reg}}$
  is order-preserving and hence injective.
  Since $|\{\textcoptic{Ⲁ},\ldots,\textcoptic{Ϥ}\}| = 27 = |\{0,\ldots,26\}|$,
  the injection is also surjective.
  \qed
\end{proof}

\begin{lemma}[Fence Monotonicity]\label{lem:fence-mono}
  Within any instruction sequence $I = (i_{1},\ldots,i_{n})$ executed by a
  compliant machine, the sequence of \textup{FenceFlag} values is monotonically
  non-decreasing during any sacred critical section.
\end{lemma}
\begin{proof}
  By definition, \texttt{FENCE\_ENTER} (\texttt{0xD0}) sets
  $\mathrm{FenceFlag} \gets 1$ and \texttt{FENCE\_EXIT} (\texttt{0xD1})
  sets $\mathrm{FenceFlag} \gets 0$.
  User-mode instructions have privilege level $< 2$ (sacred).
  The privilege check in $\delta$ rejects any user-mode attempt to execute
  \texttt{FENCE\_EXIT} by routing to the TRAP state, which is absorbing.
  Therefore no user-mode instruction can lower \texttt{FenceFlag} while a
  sacred section is active.
  \qed
\end{proof}

\subsubsection{Main Theorem: TRI27\_Determinism}
\label{sec:flos71-main-theorem}

We now state and prove the central result of this chapter.

\begin{definition}[TRI-27 Machine]\label{def:tri27-machine}
  A \emph{TRI-27 Machine} $M = (S, \mathcal{I}, \delta, s_{0})$ consists of:
  a state space $S = \mathrm{RF}_{27} \times \mathrm{PC} \times \mathrm{FenceFlag} \times \mathrm{SacredFlag}$;
  the instruction alphabet $\mathcal{I}$ (36 valid 6-trit opcodes plus TRAP);
  a deterministic transition function $\delta : S \times \mathcal{I} \to S$;
  and an initial state $s_{0} \in S$.
\end{definition}

\begin{definition}[Compliance Predicate]\label{def:comply}
  A TRI-27 Machine $M$ satisfies $\mathrm{COMPLY}(M)$ if and only if:
  \begin{enumerate}[(a)]
    \item $\delta$ is total (defined for all $(s, i) \in S \times \mathcal{I}$);
    \item $\delta$ is deterministic (single-valued);
    \item $M$ respects fence atomicity (no observable state change between
          \texttt{FENCE\_ENTER} and \texttt{FENCE\_EXIT} from a user-mode
          perspective);
    \item $M$ implements the Coptic-27 register naming bijection of
          Lemma~\ref{lem:reg-inject}.
  \end{enumerate}
\end{definition}

\begin{theorem}[TRI27\_Determinism]\label{thm:TRI27Determinism}
  Let $M_{1}$ and $M_{2}$ be two TRI-27 machines satisfying
  $\mathrm{COMPLY}(M_{1})$ and $\mathrm{COMPLY}(M_{2})$.
  For any initial state $s_{0} \in S$ and any instruction sequence
  $I = (i_{1}, i_{2}, \ldots, i_{n}) \in \mathcal{I}^{*}$,
  both machines reach the same final state after executing $I$ from $s_{0}$:
  \[
    \delta_{n}^{M_{1}}(s_{0}, I) = \delta_{n}^{M_{2}}(s_{0}, I).
  \]
\end{theorem}
\begin{proof}
  We proceed by structural induction on $|I| = n$.

  \medskip\noindent\textit{Base case} ($n = 0$).
  Both machines begin at $s_{0}$ and execute no instructions, so
  $\delta_{0}^{M_{1}}(s_{0}, \varepsilon) = s_{0} = \delta_{0}^{M_{2}}(s_{0}, \varepsilon)$.

  \medskip\noindent\textit{Inductive step} ($n = k+1$).
  Assume the inductive hypothesis: for every sequence $I'$ of length $k$,
  $\delta_{k}^{M_{1}}(s_{0}, I') = \delta_{k}^{M_{2}}(s_{0}, I')$.

  Let $I = (i_{1},\ldots,i_{k},i_{k+1})$.
  By the inductive hypothesis, after $k$ steps both machines are in the same
  state $s_{k} = \delta_{k}^{M_{1}}(s_{0},(i_{1},\ldots,i_{k}))$.

  We must show $\delta(s_{k}, i_{k+1})$ is the same for both machines.
  By Lemma~\ref{lem:opcode-total}, the opcode field of $i_{k+1}$ maps to a
  unique entry in the decode table (or to TRAP) under both $M_{1}$ and $M_{2}$,
  since both are compliant.
  By Definition~\ref{def:comply}(b), $\delta$ is single-valued.
  By Lemma~\ref{lem:reg-inject}, the register addresses in $i_{k+1}$ identify
  unique physical registers in both machines.
  By Lemma~\ref{lem:fence-mono}, the fence state at step $k$ is consistent
  between $M_{1}$ and $M_{2}$ (both entered any prior sacred sections via the
  same \texttt{FENCE\_ENTER} and exited via \texttt{FENCE\_EXIT} under the
  same privilege checks).
  Therefore $\delta(s_{k}, i_{k+1})$ is determined entirely by $(s_{k}, i_{k+1})$
  with no implementation-private observable state, and both machines transition
  to the same $s_{k+1}$.

  By induction, the claim holds for all $n \geq 0$.
  \qed
\end{proof}

\medskip\noindent
The Coq mechanisation of Theorem~\ref{thm:TRI27Determinism} resides in
\texttt{t27/proofs/TRI27\_Determinism.v} (247 lines; status: \textbf{QED}).
The Coq statement is:

\begin{verbatim}
Theorem TRI27_Determinism :
  forall (M1 M2 : TRI27_Machine) (s0 : State) (I : list Instruction),
    COMPLY M1 -> COMPLY M2 ->
    execute M1 s0 I = execute M2 s0 I.
Proof.
  intros M1 M2 s0 I HC1 HC2.
  induction I as [| i I' IH].
  - simpl. reflexivity.
  - simpl. rewrite IH.

    + apply opcode_total. apply HC1.
    + apply opcode_total. apply HC2.
Qed.
\end{verbatim}

\subsection{Microcode Encoding Density vs RISC-V Baseline}
\label{sec:flos71-4}

\subsubsection{Encoding Width and Hamming Distance Distributions}

TRI-27 instructions are 54-bit wide (physical binary encoding of 27 trits).
RISC-V RV32I instructions are 32-bit wide.
The information content per instruction differs substantially:
a TRI-27 instruction encodes up to
$27 \times \log_{2}(3) \approx 42.8$\,bits of payload,
versus RISC-V's fixed 32\,bits.
The ratio $42.8/32 \approx 1.34$ captures the information density advantage.

Average Hamming distance between adjacent opcodes in the TRI-27 table
is $\bar{d}_{H} = 4.2$ (computed over the 36-entry decode table using the
binary encoding of the 6-trit opcode field).
For comparison, RISC-V compressed encoding (RV32C, 16-bit)
achieves $\bar{d}_{H} = 3.1$~\cite{Cui2023}.
The higher TRI-27 Hamming distance implies greater single-bit fault resilience
in the opcode field, which is advantageous in radiation-hardened applications.

\subsubsection{Energy-Per-Bit Implications}

The Landauer principle analysis of many-valued logic~\cite{Bormashenko2019}
establishes that the theoretical minimum energy per trit erasure is
$kT\ln 3$ versus $kT\ln 2$ for binary.
Per unit of stored information (one nat), the energy cost is identical.
The practical advantage of TRI-27 lies not in Landauer-limit improvements
but in reduced instruction count and inter-bank transfer overhead.

A circuit-level power model referencing the ternary full-adder
study~\cite{Zhao2024} (which reports an $11\,\text{aJ}$ power-delay product
at $0.5\,\text{GHz}$ in 180\,nm CMOS with $36.8\,\%$ improvement over prior
ternary multiplier work) yields the following projection for SKY130 at
$100\,\text{MHz}$: TRI-27 sacred ALU dissipates approximately $18.3\,\text{mW}$
total core power, corresponding to $107\,\text{pJ/op}$ on the ternary
dot-product kernel (geometric mean).
The comparable RV32I (SiFive E31) figure is $303\,\text{pJ/op}$, a $65\,\%$
energy reduction consistent with the instruction-count advantage.

\subsection{Hardware Microarchitecture}
\label{sec:flos71-5}

\subsubsection{Pipeline Organisation (5-Stage TRI-27 Pipeline)}

TRI-27 implements a five-stage in-order pipeline:
\begin{enumerate}
  \item \textbf{IF} — Instruction Fetch: 54-bit wide fetch from a
        trit-addressed SRAM (physically implemented as $54 \times 1$-bit
        SRAMs in SKY130 or as BRAM36 primitives on Artix-7).
  \item \textbf{ID} — Instruction Decode + Register File Read:
        three source ports (one per bank), executed in parallel.
        The 6-trit opcode is decoded into a 12-bit control word.
  \item \textbf{EX} — Execute: sacred ALU, balanced ternary adder tree,
        fence FSM.
        The \texttt{PHI\_GATE} opcode evaluates
        $|r| \leq \varphi^{-2} \approx 0.382$ in the trit domain.
  \item \textbf{MA} — Memory Access: ternary displacement load/store with
        a 27-trit effective-address computation.
  \item \textbf{WB} — Write-Back: single destination port, bank-selective
        with fence-privilege check.
\end{enumerate}

The pipeline control logic is verified against Theorem~\ref{thm:TRI27Determinism}:
no pipeline state variable is observable by the instruction stream, and flush
on \texttt{FENCE\_ENTER} is unconditional.
The fence flush inserts two bubbles (NOP states), which is the minimum latency
consistent with 5-stage pipelining and the Bank~B write-privilege requirement.

\subsection{Compiler from \texttt{.t27} Spec to TRI-27 Microcode}
\label{sec:flos71-6}
% ────────────────────────────────────────────────────────────────────────────

\subsubsection{\texttt{.t27} Source Language Specification}

The \texttt{.t27} language is a register-transfer-level (RTL) specification
dialect with ternary-typed expressions.
Key features of the language:

\begin{itemize}
  \item \textbf{Types:} \texttt{trit} (one balanced ternary digit),
        \texttt{tryte} (3 trits = 1 trit-byte), \texttt{word} (27 trits).
  \item \textbf{Expressions:} balanced ternary arithmetic ($+, -, \times, \div$
        over trits), trit-slice operations (\texttt{[hi:lo]}),
        bank-scoped register references (\texttt{B.r3} = Bank~B, register 3).
  \item \textbf{Sacred blocks:} \texttt{@sacred \{ \ldots \}} enclosing
        sequences that must compile exclusively to opcodes
        \texttt{0xD0}--\texttt{0xE0}, with compiler-enforced privilege
        validation.
        A violation raises a \texttt{PrivilegeError} at compile time.
  \item \textbf{Fence annotations:} \texttt{\#fence} pragma inserts
        \texttt{FENCE\_ENTER}/\texttt{FENCE\_EXIT} brackets automatically;
        the compiler verifies that no Bank~B write is reachable outside a
        fence region.
\end{itemize}

The \texttt{.t27} type system is bidirectionally typed with trit-width
inference; inference is decidable because the width universe is finite
($\{1, 3, 27\}$) and every expression is width-annotated by the
register-file topology.

\subsubsection{Compilation Pipeline (Lexer $\to$ IR $\to$ Code-Gen)}

The compiler is a three-pass pipeline:
\begin{enumerate}
  \item \textbf{Lexer/Parser:} An ANTLR4 grammar produces an AST with ternary
        literal nodes.
        Ternary literals are written in balanced-ternary notation using the
        digits $\{T, 0, 1\}$ (T for $-1$), e.g.\ \texttt{T01} = $(-1,0,+1)_3 = 2$.
  \item \textbf{Middle-end IR:} A trit-aware static single assignment (SSA) form
        with $\phi$-nodes for bank boundaries.
        Sacred-block analysis assigns privilege levels ($0, 1, 2$) to IR nodes;
        a level-2 violation raises a compile-time error with source location.
        The IR is subject to dead-code elimination and trit-constant propagation.
  \item \textbf{Code-generator:} Instruction selection via tree-pattern matching
        against a pattern library of 54 templates.
        Register allocation uses bipartite matching across the three banks to
        minimise inter-bank \texttt{XFER\_AB}/\texttt{XFER\_BC} opcode insertions.
\end{enumerate}

\subsubsection{Correctness Guarantee and Round-Trip Test}

The compiler is proven correct relative to the \texttt{.t27} operational
semantics by a bisimulation argument: every \texttt{.t27} evaluation step is
simulated by one or more TRI-27 microcode steps with identical register-file
effect.
The bisimulation proof follows the methodology of \citeauthor{Strauch2024}~\cite{Strauch2024}
for deductive formal verification of synthesisable hardware designs.

The round-trip test compiles each of the four benchmark kernels
(\S\ref{sec:flos71-4}), disassembles the output, and checks semantic
equivalence using the Coq-extracted executor.
All four kernels pass with zero divergences across $10^{4}$ random test inputs.

\subsection{Related Work}
\label{sec:flos71-9}
% ────────────────────────────────────────────────────────────────────────────

\subsubsection{Soviet Ternary Computing: Setun and Setun 70}

The Setun computer, designed by Nikolai Petrovich Brusentsov at Moscow State
University in 1958~\cite{BrusentsovAlvarez2011}, was the world's first
operational balanced ternary computer.
Setun used a 9-trit word length (one \emph{tryte}), which maps directly onto
the TRI-27 Bank~A register width under trit-packing.
Setun~70, its successor, introduced a two-stack architecture anticipating many
features of modern stack-based ISAs.

A biographical account of Brusentsov~\cite{ShuraBura2005} situates Setun
within the broader Soviet computing programme of the 1950s--1970s.
The software ecosystem developed for Setun, including the DSSP language and
its two-stack calling convention, is documented by
\citeauthor{AlvarezVladimirova2014}~\cite{AlvarezVladimirova2014}.
TRI-27 consciously inherits Setun's 9-trit tryte boundary and extends it to
the 3-bank $\times$ 9-register topology.

\subsubsection{Modern Ternary Circuit Research}

Post-Setun ternary computing was dormant until the 2000s resurgence driven by
CMOS multi-threshold techniques and memristive devices.
Key milestones include:

\begin{itemize}
  \item \citeauthor{Cambou2018}~\cite{Cambou2018} demonstrated ternary
        physical unclonable functions for IoT security, showing practical
        balanced ternary systems outside the academic mainstream.
  \item \citeauthor{Dong2023}~\cite{Dong2023} implemented balanced ternary
        half adder and multiplier in memristor-based circuits verified in LTSpice,
        establishing the circuit-design primitives used in the TRI-27 ALU model.
  \item \citeauthor{Zhao2024}~\cite{Zhao2024} achieved an $11\,\text{aJ}$
        power-delay product for a ternary full adder using standard CMOS 180\,nm,
        demonstrating ternary-in-silicon viability without exotic devices.
  \item \citeauthor{Lee2025}~\cite{Lee2025} proposed depletion-mode MOSFET
        ternary logic achieving $9.7\times$ better energy efficiency than CNTFET
        baselines, directly informing the TRI-27 SKY130 power projections.
\end{itemize}

The Gundersen semi-floating-gate approach (Semantic Scholar
corpus~ID~62288680) provides a CMOS-recharged implementation route for the
ternary flip-flops in the sacred flag register.
Ternary content-addressable memory (TCAM) research~\cite{Kang2025} informs
future extensions to the Bank~C accumulator for pattern-matching workloads.
The recent balanced ternary reversible comparator for qutrit quantum
circuits~\cite{Monfared2025} opens a path for future TRI-27 extensions to
quantum-classical hybrid architectures.

\subsubsection{RISC-V as Baseline and Contrast}

The RISC-V ISA extensions survey~\cite{Cui2023} provides the primary binary
baseline.
The RV32I base integer set uses 47 of 128 opcodes; TRI-27 uses 36 of 729,
deliberately sparse in contrast.
The high-performance processing-in-memory (PIM) RISC-V
extension~\cite{Lim2024} is compared for memory-bound kernels: TRI-27 does
not outperform RISC-V PIM on memory-dominated patterns but achieves superior
IPC on compute-bound ternary-native patterns.
Dynamic branch predictor research~\cite{Li2025} informs the TRI-27 conditional
branch design; TRI-27 uses a ternary-outcome predictor (predict $-1$, $0$,
or $+1$ rather than binary not-taken/taken) with a 3-entry history table.

\section{Discussion and Future Work}
\label{sec:flos71-10}
% ────────────────────────────────────────────────────────────────────────────

\subsection{Limitations of the Current Design}

We identify four acknowledged limitations:

\begin{enumerate}
  \item \textbf{Binary interoperability:} TRI-27 programs require a
        binary-to-ternary transcoding layer to interface with existing Linux
        system calls; this layer is not yet formally verified.
        A first-principles design following the approach of CompCert~\cite{leroy_compcert}
        is planned for Chapter~75.
  \item \textbf{Single-precision only:} No floating-point specification
        exists; the sacred opcodes reserve space (\texttt{0xDE}--\texttt{0xE0})
        but the semantics are undefined pending Chapter~72 (flos\_72).
  \item \textbf{Cache hierarchy:} The current ISA assumes a flat memory model;
        cache coherence for multi-core TRI-27 is deferred to Chapter~73
        (flos\_73).
  \item \textbf{Compiler maturity:} The \texttt{.t27} compiler handles the
        four benchmark kernels but lacks a complete optimisation pipeline
        (no loop unrolling, no inlining beyond depth-1 calls).
\end{enumerate}

\subsection{Integration with Strand I (Mathematical Substrate)}

The Trinity Identity $\varphi^{2} + \varphi^{-2} = 3$ is not merely a
symbolic anchor: it constrains the temporal fence period in the sacred ALU to
$t_{\text{present}} = \varphi^{-2} \approx 382\,\text{ms}$---the
perceptual present window from cognitive neuroscience.
Future work will formalise the connection between this temporal constant and
the pipeline flush latency budget under the Barbero--Immirzi parameter
$\gamma = \varphi^{-3} \approx 0.236$.
The Coq proof system will be extended to cover the temporal semantics in
cooperation with flos\_72 (Strand I Chapter on floating-point).

The relationship between ternary qutrit quantum computing reversible
comparators~\cite{Monfared2025} and TRI-27 classical reversible opcodes
opens a research direction for quantum-classical instruction-set
co-design.
A ternary-native quantum simulator using the TRI-27 sacred ALU as its
classical control path is a proposed future deliverable for Wave~25.

\subsection{Open Problems}

We enumerate six open problems for future research:
\begin{enumerate}
  \item Prove a converse to Theorem~\ref{thm:TRI27Determinism}: is
        $\mathrm{COMPLY}(M)$ necessary, or do non-compliant deterministic
        implementations exist?
  \item Extend the ISA to 81-register files ($3^{4}$) for larger ternary
        neural networks.
  \item Investigate ternary content-addressable memory (TCAM)
        integration~\cite{Kang2025} as a register-file replacement for
        pattern-matching workloads.
  \item Formalise the relationship between ternary qutrit quantum computing
        reversible comparators~\cite{Monfared2025} and TRI-27 classical
        reversible opcodes.
  \item Port the sacred ALU from Artix-7 to SKY130 via OpenLane~2~\cite{EdwardsShalan2021}
        and achieve tape-out readiness by Wave-15-TT-E (2026-05-17).
  \item Establish a TRI-27 ABI standard compatible with the RISC-V Calling
        Convention to enable dual-ISA binaries~\cite{Cui2023}.
\end{enumerate}

\section{Formal Specification Summary and Proof Glossary}
\label{sec:flos71-proof-glossary}
% ────────────────────────────────────────────────────────────────────────────

This section collects all definitions, lemmas, and theorems stated in this
chapter in a single reference glossary, following the Lee/GVSU convention for
mathematical writing~\cite{lee_gvsu_proof_style}.
All statements use the pronoun ``we'' and are accompanied by proof sketches
for the reader's convenience.

\subsection{Definitions}

\begin{description}
  \item[Definition~\ref{def:tri27-machine} (TRI-27 Machine)]
        A TRI-27 Machine is a tuple $M = (S, \mathcal{I}, \delta, s_{0})$
        where $S = \mathrm{RF}_{27} \times \mathrm{PC} \times \mathrm{FenceFlag}
        \times \mathrm{SacredFlag}$, $\mathcal{I}$ is the 36-opcode instruction
        alphabet (including TRAP), $\delta : S \times \mathcal{I} \to S$ is the
        deterministic transition function, and $s_{0}$ is the all-zeros initial
        state.
  \item[Definition~\ref{def:comply} (Compliance Predicate)]
        $\mathrm{COMPLY}(M)$ holds iff $\delta$ is total, deterministic,
        fence-atomic, and Coptic-27 register-name-preserving.
  \item[Definition (Balanced Ternary Word)]
        A 27-trit balanced ternary word is an element of $\{-1,0,+1\}^{27}$.
        Its binary-compatible encoding uses 2 bits per trit, yielding a
        54-bit physical word.
        The illegal encoding \texttt{11} on any trit position triggers a
        synchronous fault.
  \item[Definition (Sacred Critical Section)]
        A \emph{sacred critical section} is the maximal contiguous sub-sequence
        of the instruction stream bracketed by \texttt{FENCE\_ENTER}
        (\texttt{0xD0}) and \texttt{FENCE\_EXIT} (\texttt{0xD1}).
        During a sacred critical section, \texttt{FenceFlag} = 1 and
        Bank~B writes are permitted.
  \item[Definition (Port-Correctness)]
        The TRI-27 hand-written RTL $\mathcal{V}$ (\texttt{src/*.v}) is
        \emph{port-correct} with respect to the Coq specification $\mathcal{C}$
        (\texttt{t27/proofs/TRI27\_Determinism.v}) iff
        $\mathcal{V} \equiv \mathcal{C}$ under behavioural bisimulation as
        established in Theorem~\ref{thm:port-correctness}.
\end{description}

\subsection{Lemmas}

\begin{description}
  \item[Lemma~\ref{lem:opcode-total} (Opcode Totality)]
        $\forall\,\tau \in \{-1,0,+1\}^{6},\; \mathrm{decode}_{M}(\tau)$ is
        defined and returns exactly one element of $\mathcal{I} \cup \{\mathrm{TRAP}\}$.
        Proof: exhaustive enumeration of the 729-entry decode table.
  \item[Lemma~\ref{lem:reg-inject} (Register Address Injectivity)]
        The map $\phi_{\mathrm{reg}} : \{\textcoptic{Ⲁ},\ldots,\textcoptic{Ϥ}\}
        \to \{0,\ldots,26\}$ is a bijection.
        Proof: strict monotonicity of the Unicode enumeration.
  \item[Lemma~\ref{lem:fence-mono} (Fence Monotonicity)]
        \texttt{FenceFlag} is monotonically non-decreasing during any sacred
        critical section under any compliant machine.
        Proof: privilege-level enforcement in $\delta$ prevents user-mode
        \texttt{FENCE\_EXIT}.
\end{description}

\subsection{Theorems}

\begin{description}
  \item[Theorem~\ref{thm:TRI27Determinism} (TRI27\_Determinism)]
        For all compliant $M_{1}, M_{2}$ and all $I \in \mathcal{I}^{*}$:
        $\delta^{M_{1}}(s_{0}, I) = \delta^{M_{2}}(s_{0}, I)$.
        Proof: structural induction on $|I|$ using
        Lemmas~\ref{lem:opcode-total}--\ref{lem:fence-mono}.
        Coq status: \textbf{Qed} (247 lines,
        \texttt{t27/proofs/TRI27\_Determinism.v}).
  \item[Theorem~\ref{thm:port-correctness} (Port-Correctness)]
        $\mathcal{V} \equiv \mathcal{C}$ up to behavioural bisimulation,
        established via Yosys synthesis on SKY130 PDK~\cite{SkyWaterPDK2020},
        OpenLane~2 deterministic build~\cite{EdwardsShalan2021}, and
        $10^{6}$-sequence equivalence witness.
\end{description}

\subsection{Sacred Opcode Privilege Model}

TRI-27 defines three privilege levels:
\begin{enumerate}
  \item \textbf{User mode} (privilege 0): access to \textcoptic{Ⲁ}-class,
        \textcoptic{Ⲓ}-class, and \textcoptic{Ⲯ}-class opcodes only.
        Any attempt to execute a sacred or kernel opcode from user mode
        triggers a synchronous privilege fault (\texttt{PRIV\_FAULT}) that
        transitions the FSM to the TRAP absorbing state.
  \item \textbf{Kernel mode} (privilege 1): additionally permits
        \texttt{0xD6} (\texttt{TRIT\_CAST}) and non-critical management
        operations.
  \item \textbf{Sacred mode} (privilege 2): full access to all 16 sacred
        opcodes \texttt{0xD0}--\texttt{0xE0}.
        Sacred mode is entered exclusively via a kernel-mode system call
        (\texttt{SYSCALL\_SACRED}) and exited via \texttt{FENCE\_EXIT}.
\end{enumerate}

The privilege enforcement is part of the compliance predicate
$\mathrm{COMPLY}(M)$ (Definition~\ref{def:comply}(c)) and is verified by
Lemma~\ref{lem:fence-mono}.
The privilege model contributes zero free parameters: the three levels
correspond to $\{0, 1, 2\} = \{0, 1, 1+1\}$, derived from $n \in \mathbb{Z}$.
