\section*{C.1 Purpose}
\label{app:C-purpose}
\addcontentsline{toc}{section}{C.1 Purpose}

The verify-check protocol is a gate in the Trinity S$^{3}$AI build
pipeline that runs after every \texttt{cargo build} and before every
\texttt{cargo clippy}. It ensures that the $38$ architectural
invariants of the GF16/IGLA/VSA stack hold, and that the $18$
Catalog42 formula fits (selected from the $42$-entry catalogue by the
criterion ``Vasilev formula present in Coq'') produce residuals
within their declared tolerance bands. This appendix documents the
complete checklist.

\section*{C.2 The 38 Verify Checks}
\label{app:C-verify-38}
\addcontentsline{toc}{section}{C.2 The 38 Verify Checks}

The checks are organised by subsystem.

\subsection*{C.2.1 GF16 Arithmetic (Checks 1--10)}

\begin{enumerate}
\item[\textbf{V01}] $\varphi^2 + \varphi^{-2} = 3$ to $64$-bit precision.
\item[\textbf{V02}] GF16 $\texttt{neg\_one\_f16} + \texttt{pos\_one\_f16} = \texttt{zero\_f16}$.
\item[\textbf{V03}] GF16 multiply identity: $x \times \texttt{pos\_one\_f16} = x$ for unity-band $x$.
\item[\textbf{V04}] GF16 round-trip: $\mathrm{quantise}(\mathrm{dequantise}(x)) = x$ for safe-domain $x$.
\item[\textbf{V05}] INV-3 upper bound: every GF16 MAC result $\leq \varphi^2$ in absolute value.
\item[\textbf{V06}] INV-3 lower bound: every GF16 MAC result $\geq -\varphi^2$.
\item[\textbf{V07}] Three-band partition: $|\{x : \hat{E}(x) < B\}| + |\{x : \hat{E}(x) = B\}| + |\{x : \hat{E}(x) > B\}| = |\mathbb{F}_{16}^{\times}|$.
\item[\textbf{V08}] GF16 field arithmetic: $a \cdot (b + c) = a \cdot b + a \cdot c$ for $10^4$ random triples.
\item[\textbf{V09}] Silicon anchor: \texttt{dot4(v1,v2,v3,v4) = 0x47C0} for canonical basis.
\item[\textbf{V10}] Machine epsilon: $|1 \oplus \varepsilon_{\mathrm{GF16}} - 1| \leq 2^{-10}$.
\end{enumerate}

\subsection*{C.2.2 IGLA RACE Scheduler (Checks 11--20)}

\begin{enumerate}
\item[\textbf{V11}] Period lock: scheduler macro period $= L_8 = 47$ ticks.
\item[\textbf{V12}] Period lock: scheduler micro period $= L_7 = 29$ sub-ticks.
\item[\textbf{V13}] Weight bounds: $w_i(t) \in [\varphi^{-2}, \varphi^{2}]$ for all agents $i$ and ticks $t$.
\item[\textbf{V14}] Weight sum: $\sum_i w_i(t) = M$ (normalised to agent count).
\item[\textbf{V15}] Agent count: $M \leq L_8 = 47$.
\item[\textbf{V16}] $\varphi$-discount monotonicity: $\Delta t_1 < \Delta t_2 \Rightarrow \varphi^{-\Delta t_1} > \varphi^{-\Delta t_2}$.
\item[\textbf{V17}] Sealed-seed hash: SHA-256 of config matches committed hash.
\item[\textbf{V18}] Seed-pool exhaustiveness: all $7$ seeds used in round-robin over $7$ runs.
\item[\textbf{V19}] Liveness: every agent scheduled at least once per $2 L_8$ ticks.
\item[\textbf{V20}] Fairness: $\max_i \Delta t_i / \min_i \Delta t_i \leq L_7$.
\end{enumerate}

\subsection*{C.2.3 VSA+AR Module (Checks 21--30)}

\begin{enumerate}
\item[\textbf{V21}] Ternary binding self-inverse: $(u \circledast v) \circledast (-u) = v$ for $10^3$ random pairs.
\item[\textbf{V22}] Hypervector dimension: $D = F_{20} = 6765$.
\item[\textbf{V23}] Density: $\rho^* = \varphi^{-2} \approx 0.382$ within $10^{-6}$.
\item[\textbf{V24}] Recall accuracy: top-1 $\geq 99.9\%$ on $M = 47$ stored vectors.
\item[\textbf{V25}] Inner product bound: $|\langle \mathbf{q}, \mathbf{c}_j \rangle| / D < 1/\sqrt{D}$ for mismatched pairs.
\item[\textbf{V26}] Phi-RoPE orthogonality: $|\langle \mathbf{v}_p, \mathbf{v}_q \rangle| / D < 0.05$ for $|p - q| \leq F_{21}$.
\item[\textbf{V27}] MAC overflow: zero overflow events over $1003$ tokens.
\item[\textbf{V28}] AR memory capacity: $M \leq L_8 = 47$ stored vectors.
\item[\textbf{V29}] Ternary exhaustiveness: every component $\in \{-1, 0, +1\}$.
\item[\textbf{V30}] Accumulator width: $24$ bits suffices for $D \cdot \varphi^2 = F_{22} = 17711$.
\end{enumerate}

\subsection*{C.2.4 KAT Module (Checks 31--38)}

\begin{enumerate}
\item[\textbf{V31}] KAT channel count: $2n + 1 = 9$ for $n = 4$.
\item[\textbf{V32}] LUT grid resolution: $29 = L_7$ entries per LUT.
\item[\textbf{V33}] LUT total storage: $36 \times 29 \times 16 = 16704 \leq 18432$ (fits $1$ BRAM tile).
\item[\textbf{V34}] KAT forward-pass latency: $\leq 12$ cycles at $92$\,MHz.
\item[\textbf{V35}] Outer normalisation: $1/\sqrt{3}$ applied to all channels.
\item[\textbf{V36}] Ternary output: all outer-function outputs $\in \{-1, 0, +1\}$.
\item[\textbf{V37}] Approximation error: $\|f - \hat{f}_{\mathrm{KAT}}\|_\infty \leq 9 L_f / (L_7 \sqrt{3}) + 9 \varepsilon_{\mathrm{GF16}}$.
\item[\textbf{V38}] Pipeline slack: $L_7 - 12 = 17$ idle cycles per KAT evaluation.
\end{enumerate}

\section*{C.4 Consistency Guarantee}
\label{app:C-consistency}
\addcontentsline{toc}{section}{C.4 Consistency Guarantee}

For all $18$ formula fits, the Coq-evaluated residual and the
Rust-runtime residual agree to all reported decimal places. This
consistency is enforced by the build pipeline: the CI job
\texttt{verify-checks} runs the Coq evaluator on each formula,
extracts the residual, and compares it to the Rust-computed value. Any
discrepancy triggers a build failure. The sealed-seed protocol
(App.N) ensures that the random inputs to the evaluator are
deterministic across runs, eliminating the possibility of
seed-dependent drift.
